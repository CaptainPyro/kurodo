1. PROJECT OVERVIEW
============================================================

Kurodo is a lightweight VS Code extension that provides a
Claude Code-like agentic coding experience. It enables users
to interact with Claude AI models directly within VS Code to
perform software engineering tasks.

Key capabilities:
- Chat interface with streaming responses
- File operations (read, write, edit, delete, list)
- Terminal command execution with risk classification
- Git integration (status, commit)
- MCP (Model Context Protocol) server support
- Session persistence
- TRUE Auto Mode for autonomous routine work

The project was created to provide a self-contained, privacy-
respecting alternative to cloud-based coding assistants while
maintaining robust security measures.

3. ARCHITECTURE
============================================================

The extension follows a layered architecture:

USER
  |
  v
WEBVIEW (Chat UI)
  |
  v
CHAT VIEW PROVIDER (message routing)
  |
  v
AGENT RUNTIME (conversation loop)
  |
  v
ANTHROPIC PROVIDER (API communication)
  |
  v
TOOL EXECUTOR (tool dispatch)
  |
  +---> PERMISSION ENGINE (risk evaluation)
  |
  +---> INDIVIDUAL TOOLS (FileTools, TerminalTools, etc.)
  |
  v
TOOL RESULT --> back to AGENT RUNTIME --> PROVIDER --> UI

5. AGENT RUNTIME
============================================================

Location: src/agent/AgentRuntime.ts

The AgentRuntime manages the conversation loop:

1. User sends message
2. Message added to session
3. Provider called with messages + tool definitions
4. Streaming response received
5. If tool calls present:
   a. Evaluate risk level
   b. Check permission engine
   c. Request approval if needed
   d. Execute tool
   e. Add result to messages
   f. Loop back to step 3
6. If no tool calls, conversation turn complete

States:
- idle: Waiting for user input
- processing: Generating response
- tool_pending: Waiting for tool approval
- error: Error occurred

The runtime integrates with MCPManager to register MCP tools
dynamically via refreshMCPTools().

7. TOOL SYSTEM
============================================================

Location: src/tools/

Tools implement the Tool interface:
- name: string
- description: string

- inputSchema: JSON Schema
- execute(input, context): Promise<ToolResult>

Registered Tools:

- read_file: Read file contents (low risk)
- write_file: Create/overwrite file (medium risk)
- edit_file: Find-and-replace edit (medium risk)
- list_files: Glob pattern matching (low risk)
- delete_file: Delete file (high risk)

SEARCH TOOLS (SearchTools.ts):
- search_files: Content search with regex (low risk)

TERMINAL TOOLS (TerminalTools.ts):
- run_command: Execute shell command (dynamic risk)
- git_status: Get git status (low risk)
- git_commit: Stage and commit (medium risk)

MCP TOOLS:
- Dynamically registered from MCP servers
- Prefixed with mcp_{server}_{tool}
- Default to medium risk

============================================================
8. PERMISSION ENGINE
============================================================

Location: src/permission/PermissionEngine.ts

Evaluates tool calls against policies to determine:
- allowed: boolean
- requiresConfirmation: boolean
- reason: string (if denied)

Policies:

1. High-Risk Pattern Policy
   - Detects dangerous patterns (rm -rf, git reset --hard, etc.)
   - Always requires confirmation for high-risk operations

2. Auto Mode Policy
   - Low risk: Always allowed
   - Medium risk: Allowed in Auto Mode, confirmation otherwise
   - High risk: Always requires confirmation

3. Workspace Boundary Policy
   - Defense-in-depth path validation
   - Blocks operations outside workspace

Always-Confirm Patterns:
- delete_file tool
- rm with recursive/force flags
- git push --force
- git reset --hard
- git clean -f
- DROP TABLE/DATABASE
- format, mkfs, dd if=

Always-Allow Patterns:
- read_file
- list_files
- search_files
- git_status

============================================================
9. AUTO MODE
============================================================

Auto Mode is a TRUE risk-based autonomous operation mode.

When Auto Mode is ENABLED:
- Low risk operations: Execute immediately
- Medium risk operations: Execute immediately
- High risk operations: Always require approval

When Auto Mode is DISABLED:
- Low risk operations: Execute immediately
- Medium risk operations: Require approval
- High risk operations: Require approval

This enables the agent to work autonomously on routine tasks
(file reads, searches, normal edits, safe commands) while
maintaining safety for genuinely dangerous operations.

============================================================
10. FILESYSTEM SECURITY
============================================================

Location: src/tools/FileTools.ts (validatePath function)

All file operations validate paths to prevent workspace escape:

1. Resolve the workspace root to absolute path
2. Resolve the target path (handling both relative and absolute)
3. Compute relative path from workspace to target
4. If relative path starts with '..' or is absolute, DENY

This prevents:
- Path traversal (../../../etc/passwd)
- Absolute paths outside workspace (/etc/passwd)
- Complex traversal (src/../../../etc/passwd)

The validation is applied in:
- ReadFileTool
- WriteFileTool
- EditFileTool
- DeleteFileTool

Additionally, the PermissionEngine has defense-in-depth
workspace boundary checking.

============================================================
11. TERMINAL SECURITY
============================================================

Location: src/tools/TerminalTools.ts

Commands are classified using regex patterns:

DANGEROUS_PATTERNS (high risk):
- rm -rf, rm -r, rm -f
- rmdir, del /s
- format, mkfs, dd if=
- chmod 777, chown -R root
- curl|bash, wget|sh, eval
- git push --force, reset --hard, clean -f
- DROP TABLE/DATABASE, TRUNCATE
- shutdown, reboot, init 0-6
- kill -9 -1, killall, pkill -9
- Fork bombs
- sudo rm, sudo dd
- PATH manipulation
- Credential file access

SAFE_PATTERNS (low risk):
- ls, dir, pwd
- cat (without pipes), head, tail, less, more
- grep, rg, find -name, which, whereis
- git status/log/diff/branch/show
- Version checks (node -v, npm -v, etc.)
- npm list/ls/outdated/test/run/install
- echo, env, printenv, whoami, hostname, date
- df, du, free, ps, uname
- make, cmake, cargo build/test, go build/test
- cd, mkdir, touch

Command chaining (;, &, |) triggers additional analysis
of each part.

12. MCP
============================================================

Location: src/mcp/

MCP (Model Context Protocol) enables integration with external
tool servers.

Configuration:
Settings key: kurodo.mcpServers
Format: { "serverName": { command, args, env, cwd } }

Example:
{
  "kurodo.mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path"]
    }
  }
}

Implementation:
- MCPClient spawns server process
- Communicates via JSON-RPC over stdio
- Discovers tools via tools/list
- Executes tools via tools/call
- MCPToolAdapter wraps MCP tools as internal Tools
- MCPManager coordinates server lifecycle
- Configuration changes trigger automatic reconnection

MCP tools are prefixed: mcp_{serverName}_{toolName}
They default to medium risk level.

16. STREAMING
============================================================

Streaming is implemented via the Anthropic SDK's stream() method.

Events handled:
- message_start: Begin message
- content_block_start: Start of text or tool_use block
- content_block_delta: Incremental content (text or JSON)
- content_block_stop: End of block, parse tool input
- message_stop/message_delta: End of message

Text is streamed incrementally to the UI via agent events.
Tool calls are collected and executed after the message completes.

31. IMPORTANT DECISIONS
============================================================

1. TRUE Auto Mode
   Decision: Auto Mode should be genuinely autonomous for
   routine work, not just a "skip all prompts" toggle.
   Rationale: Balance usability with safety.

2. Defense-in-Depth Security
   Decision: Validate paths in both tools AND permission engine.
   Rationale: Multiple layers prevent security bypass.

3. Regex-Based Command Detection
   Decision: Use regex patterns instead of simple substrings.
   Rationale: More accurate, handles variations and flags.

4. MCP as Optional
   Decision: Extension works without MCP servers.
   Rationale: Simpler default experience.

5. Session Persistence
   Decision: Use VS Code globalState, not workspace state.
   Rationale: Sessions persist across workspaces.

============================================================
32. REJECTED APPROACHES
============================================================

1. Simple Substring Matching for Commands
   Rejected: Too easy to bypass (e.g., "rm" matches "mkdir")
   Adopted: Regex patterns with word boundaries

2. Path Validation via String Contains
   Rejected: "../" check can be bypassed with encoding
   Adopted: path.resolve() + path.relative() normalization

3. Auto Mode as All-or-Nothing
   Rejected: Either too restrictive or too dangerous
   Adopted: Risk-based gradation
